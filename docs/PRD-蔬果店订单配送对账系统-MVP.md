# PRD：蔬果店「饭店订单 / 配送 / 对账」系统（MVP）

版本：v0.1（聊天定稿稿）  
目标交付形态：店内 Web 管理端 + 饭店端 H5（含消息提醒）  

---

## 1. 背景与现状

家里经营蔬菜水果店，对外零售，同时与附近饭店等客户存在长期预定往来：饭店每天预定一批蔬菜水果，店方次日配送上门。当前整体以纸本记录为主：每家饭店一本本子，送货时收下一天（或下午）需求，缺货/加单/退货也以线下沟通+纸面签单记录；周结对账依赖手写汇总。

### 1.1 当前规模与人员
- 合作饭店/客户：约 6–20 家
- 店内人员：2–3 人（个人店）
- 配送：1–2 人；距离近，可随时送（常见 08:00 左右送）

---

## 2. 主要问题与痛点（优先级最高）
1) **改单/补单同步混乱**  
截止前后、配送前的临时加减菜很难被统一记录和追溯，导致漏单/错单/争议。

2) **对账结算麻烦**  
周结依赖手写汇总，出错成本高；争议时缺乏“最终发货明细 + 留证”。

---

## 3. 产品目标与成功指标

### 3.1 产品目标（MVP）
跑通并固化一个可落地的闭环：
**下单/改单 → 店内汇总备货（可导出/打印）→ 配送签收留证 → 周结对账单 + 欠款记录**

### 3.2 成功指标（建议）
- 汇总拣货清单时间：从手工整理下降到可在 1–3 分钟内导出
- 对账差异/争议次数：显著下降（有“最终发货明细 + 签收留证”可追溯）
- 改单可追溯率：100%（谁、何时、改了什么、有无审批）
- 签收留证覆盖率：100%（至少 1 张照片 + 签收人）

---

## 4. 用户与角色

### 4.1 店内角色
- 老板：总体管理、价格维护、对账与欠款
- 店员/分拣员：汇总、拣货、处理缺货/替代
- 配送员：配送、签收留证

### 4.2 客户侧角色
- 饭店下单人：下单、截止前改单、截止后请求改单、替代确认、查看对账单

---

## 5. 产品范围与边界

### 5.1 MVP 必做
**饭店端（H5/Web）**
- 下单（商品/单位/数量/备注），支持“复制昨日”并可编辑
- 截止前直接改单；截止后提交“请求改单”（店内审批）
- 下单即展示价格（当日“今日价”）
- 替代确认中心：店内发起替代建议后，饭店确认/拒绝
- 查看周结对账单与欠款状态

**店内 Web 管理端**
- 客户管理：截止时间可按客户配置（默认 20:00）
- 商品管理：支持单位（斤/箱/袋/把）配置
- 今日价维护：按天维护并在下单时展示；订单提交锁价
- 订单中心：查看订单、处理“截止后改单请求”
- 汇总与拣货单：按客户/按品类汇总，导出 Excel/PDF
- 缺货/部分发货：录入最终发货数量/缺货原因
- 替代建议发起：生成待确认替代请求
- 配送签收：配送员上传≥1张照片 + 填写签收人姓名
- 周结对账单：按客户生成对账单；记录已收/未收/部分收与欠款余额

**关键强规则**
- **替代必须客户确认**：你发起替代 → 饭店确认后才算最终发货
- **替代待确认的订单不允许签收**（强制卡控，避免对账争议）
- **签收照片必填**：≥1 张，由配送员送达后自行拍照上传（不要求客户拍）

### 5.2 MVP 不做（明确排除）
- 库存/采购联动（先跑通订单闭环）
- 线上收款自动对账（先做对账单+欠款记录）
- 复杂营销与会员体系

---

## 6. 业务规则（全局）

### 6.1 下单/改单截止时间
- 默认截止时间：**每日 20:00**
- 支持按客户单独调整截止时间
- 20:00 前：客户可直接改单（立即生效）
- 20:00 后：客户只能发起“请求改单”，需店内审批同意后生效

- 结算周期（settlement_cycle）字段V0仅作文本备注（如“每周一结”），不参与自动逻辑；对账单生成时由老板手动选择起止日期，后续版本再增强自动周期生成

### 6.2 价格规则
- 店内每天维护“今日价”（建议在前一天晚上或当天早上维护）
- 下单时展示价格
- 当日未维护定价时，沿用该商品最近一次定价（前端标注“沿用X月X日定价”）；无任何历史定价的商品不可下单
- 订单提交后**锁价**（写入订单明细价格快照），后续改价不影响历史对账

### 6.3 单位规则
- 商品支持多单位：斤/箱/袋/把
- 每个商品配置默认单位；下单时允许选择（或按商品固定）

### 6.4 缺货/部分发货/替代
- 缺货时支持：部分发货（实际数量）/无法供货（缺货）
- 替代：店内发起替代建议，必须饭店确认后才计入最终发货
- 若存在“待确认替代”或“待处理改单”，订单不可签收

### 6.5 签收留证
- 配送员填写签收人姓名、上传 ≥1 张照片后方可完成签收

---

## 7. 核心流程（MVP）

### 7.1 下单（含复制昨日）
1. 饭店选择送达日期 → 添加商品明细（商品/单位/数量/备注）
2. 可“一键复制昨日订单”生成草稿再编辑
3. 提交后订单状态=已提交；截止前可直接修改

### 7.2 改单（截止前/后）
- 截止前：直接编辑订单明细，系统记录变更日志
- 截止后：提交“请求改单”→ 店内审批（同意/拒绝）→ 结果回传饭店

### 7.3 店内汇总备货
- 店内 Web 按日期查看订单汇总（按客户/按品类）
- 导出拣货单（Excel/PDF），用于分拣或打印

### 7.4 缺货与替代确认（强卡控）
- 店内对缺货商品可发起替代建议（替代商品/数量/备注）
- 饭店在H5/Web“替代确认中心”确认/拒绝
- **未确认替代 → 订单不可签收**

### 7.5 配送签收
配送员到店 → 填写签收人姓名 + 上传 ≥1 张照片 → 订单状态=已签收

### 7.6 周结对账与欠款
按客户生成周期对账单（订单列表+合计）→ 记录收款状态与欠款余额。

## 8. 功能需求（按端拆分）

### 8.1 饭店端（H5/Web）
1. 下单/编辑：商品、单位、数量、备注
2. 复制昨日：生成草稿并可编辑
3. 截止前改单：直接生效；截止后请求改单：待审批
4. 替代确认中心：确认/拒绝（需消息提醒）
5. 订单查询：今日/历史订单与状态
6. 对账单查询：周结对账单、欠款状态

### 8.2 店内 Web 管理端
1. 客户管理：截止时间、结算周期、启停用
2. 商品管理：单位配置、上下架
3. 今日价管理：按天维护，支持快速批量修改
4. 订单中心：查看订单、变更记录、审批改单请求
5. 汇总与导出：按客户/品类汇总，导出拣货单
6. 缺货/部分发货：录入最终发货数量、缺货原因
7. 替代建议发起：生成替代待确认请求，并跟踪状态
8. 配送签收：查看签收照片、签收人、配送员
9. 周结对账：生成对账单、记录应收/已收/欠款

### 8.3 配送员（移动端页面/模式）
1. 今日配送单列表
2. 签收页：强校验（不得有“替代待确认/改单待处理”），拍照必填

## 9. 消息提醒（方案 B：必须做）
当存在“替代待确认”（或截止后改单审批结果）时，系统向饭店侧发送提醒。

### 9.1 提醒触发点
- 店内发起替代建议 → 立即提醒
- 店内审批截止后改单请求（同意/拒绝）→ 立即提醒
- （可选）临近截止时间提醒：例如 19:30 提醒未提交客户

### 9.2 提醒方式（实现顺序建议）
> 注意：H5方案无法使用小程序订阅消息/模板消息，此路不通。
> V1提醒依赖以下方式：
1) 企业微信应用消息（主要方式，若使用企业微信生态）  
2) 兜底：短信/电话（仅运营策略，不在系统内自动发送也可）

## 11. 验收标准（关键可测）
1) 默认截止 20:00；支持客户级配置并生效  
2) 20:00 前改单直接生效；20:00 后改单必须审批  
3) 今日价维护后饭店端展示正确；订单提交锁价  
4) 汇总支持按客户/品类两种视图；可导出拣货单  
5) 替代建议可发起；饭店可确认/拒绝；未确认则订单不可签收  
6) 签收必须：签收人姓名 + ≥1 张照片（配送员上传）  
7) 对账单金额按“最终发货明细”计算；欠款余额计算正确  
8) 消息提醒：替代待确认/审批结果能触达饭店侧

---

## 12. 里程碑与迭代计划（可落地路径）

### V0：最快跑通闭环（1–2 周）
- 店内 Web：客户/商品/今日价、订单汇总导出、对账单+欠款记录
- 饭店端：下单/复制昨日/截止前改单/截止后改单请求（可先不做替代确认，仅留痕+电话确认）

### V1：标准 MVP（2–6 周）
- 替代确认中心 + 消息提醒（方案 B）
- “替代待确认不可签收”强卡控
- 配送签收：拍照必填 + 留证查看

### V2：增强（后续）
- 库存/采购联动、供应商进货清单
- 客户专属价、历史价、统计报表
- 多批次配送、路线优化

---

## 13. 风险与对策（简要）
- 饭店不及时确认替代导致配送卡住  
  - 对策：强提醒 + 店内看板 + 可在店内一键“改为缺货/部分发货”兜底
- 今日价维护不及时引发争议  
  - 对策：维护流程固化（前一晚/早上），并锁价留痕
- 拍照留证执行不到位  
  - 对策：签收强校验（无照片不可签收）
